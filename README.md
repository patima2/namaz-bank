# بانک طرح درس نماز — راهنمای ساده

اطلاعات این سایت در یک دیتابیس آنلاین (Supabase) ذخیره می‌شود. هر کسی لینک را باز کند همان اطلاعات را می‌بیند، ولی فقط شما (مدیر) می‌توانید اضافه، ویرایش یا حذف کنید.

> نام دکمه‌ها و منوها در Supabase و GitHub ممکن است کمی فرق کرده باشد؛ دنبال همان کلمه‌های انگلیسی بگردید.

**فایل‌ها:** `index.html` (خود سایت) · `config.js` (آدرس و کلید اتصال) · `schema.sql` (ساخت دیتابیس) · `README.md` (همین راهنما)

## مرحله ۱ — ساخت حساب Supabase
1. به supabase.com بروید و **Start your project** را بزنید.
2. با ایمیل یا حساب Google/GitHub ثبت‌نام کنید. اگر ایمیل تأیید آمد، لینک داخلش را بزنید.

## مرحله ۲ — ساخت پروژه
1. **New project** را بزنید.
2. در **Name** بنویسید `namaz-bank`.
3. در **Database Password** روی **Generate a password** بزنید و رمز را جایی ذخیره کنید (برای کار روزمره لازم نیست).
4. **Region** را نزدیک‌ترین گزینه انتخاب کنید (مثلاً Frankfurt) و **Create new project** را بزنید. ۱ تا ۲ دقیقه صبر کنید.

## مرحله ۳ — ساخت دیتابیس
1. در منوی کنار صفحه روی **SQL Editor** بزنید، سپس **New query**.
2. فایل `schema.sql` را با Notepad باز کنید، `Ctrl+A` و بعد `Ctrl+C` بزنید (همه متن کپی می‌شود).
3. داخل کادر Supabase کلیک کنید و `Ctrl+V` بزنید (Paste).
4. دکمه سبز **Run** را بزنید. باید پیام موفقیت (Success) ببینید.
5. اگر پیامی درباره «destructive / عملیات خطرناک» آمد، **Run this query** را بزنید؛ مشکلی ندارد.
6. بررسی: در منوی **Table Editor** باید جدول‌های `categories` و `contents` را ببینید و داخل `categories` دسته‌های اولیه باشند.

## مرحله ۴ — ساخت حساب مدیر
1. از منو **Authentication** ← **Users** ← **Add user** ← **Create new user**.
2. ایمیل و رمز دلخواه (حداقل ۸ حرف) بنویسید و تیک **Auto Confirm User** را بزنید، سپس **Create user**.
3. همین ایمیل و رمز، ورود شما به سایت است. اولین کاربرِ ساخته‌شده خودکار مدیر می‌شود؛ کاربران بعدی فقط می‌توانند ببینند.

## مرحله ۵ — گرفتن اطلاعات اتصال
1. پایین منوی کنار صفحه روی **Project Settings** (چرخ‌دنده) بزنید و بخش **API Keys** (یا **Data API**) را باز کنید.
2. این دو را کپی کنید: **Project URL** (شبیه `https://abcd.supabase.co`) و **Publishable key** (در نسخه‌های قدیمی‌تر اسمش `anon public` است).
3. این کلید «عمومی» است و گذاشتنش در سایت امن است. هرگز کلید `secret` یا `service_role` را در سایت نگذارید.

## مرحله ۶ — قرار دادن سایت روی GitHub Pages
1. در github.com ثبت‌نام کنید. روی **New repository** بزنید، در Repository name بنویسید `namaz-bank`، گزینه **Public** را انتخاب و **Create repository** را بزنید.
2. فایل ZIP را روی کامپیوتر **Extract** کنید. در صفحه مخزن روی **uploading an existing file** بزنید و **فایل‌های داخل پوشه** (`index.html`، `config.js` و بقیه) را بکشید و رها کنید. خودِ ZIP را آپلود نکنید. بعد **Commit changes** را بزنید.
3. روی فایل `config.js` کلیک کنید، سپس آیکون مداد (**Edit**) را بزنید. بین دو گیومه جلوی `url:` آدرس Project URL و بین دو گیومه جلوی `key:` همان Publishable key را Paste کنید. مثال:
   `url: "https://abcd.supabase.co",` و `key: "کلید طولانی"`
   سپس **Commit changes** را بزنید.
4. بالای صفحه **Settings** ← منوی **Pages**. در **Source** گزینه **Deploy from a branch** را بگذارید، در **Branch** گزینه `main` و پوشه `/ (root)` را انتخاب و **Save** بزنید.

## مرحله ۷ — گرفتن لینک نهایی
۱ تا ۲ دقیقه بعد صفحه Pages را دوباره باز کنید (Refresh). بالای صفحه نوشته می‌شود **Your site is live at ...**؛ آن لینک را کپی کنید و برای دوستانتان بفرستید. شکل لینک: `https://نام-کاربری-شما.github.io/namaz-bank/`

## کار با سایت
- **ورود مدیر:** دکمه «ورود مدیر» بالای سایت ← ایمیل و رمز مرحله ۴.
- **افزودن دسته‌بندی:** بعد از ورود، در صفحه اصلی دکمه «+ افزودن دسته‌بندی» ← نام و توضیح (و در صورت نیاز دسته والد) ← ذخیره.
- **افزودن زیرشاخه:** وارد دسته مورد نظر شوید ← «+ افزودن زیرشاخه».
- **ویرایش یا حذف دسته:** داخل همان دسته، دکمه «ویرایش» یا «حذف». اگر دسته محتوا یا زیرشاخه داشته باشد قبل از حذف هشدار می‌دهد.
- **افزودن طرح درس (یا داستان، روایت، آیه، حدیث، فعالیت...):** داخل دسته یا زیرشاخه ← «+ افزودن محتوا» ← فرم را پر کنید و «نوع محتوا» را انتخاب کنید ← ذخیره. ویرایش و حذف روی کارت هر محتوا هست.
- **جستجو و فیلتر:** کادر بالای سایت. در صفحه نتایج می‌توانید بر اساس نوع، گروه سنی و دسته/زیرشاخه فیلتر کنید.
- **یادداشت شخصی:** فقط مدیر می‌بیند.
- **گرفتن Backup:** بعد از ورود، «مدیریت» ← «خروجی گرفتن از اطلاعات». یک فایل `.json` دانلود می‌شود؛ آن را جای امن نگه دارید و هر چند وقت یک‌بار بگیرید.
- **برگرداندن Backup:** «مدیریت» ← «وارد کردن اطلاعات» ← فایل `.json` را انتخاب کنید ← تأیید.

## اگر خطا دیدید
- **«راه‌اندازی هنوز کامل نشده»:** `config.js` پر نشده یا تغییرش ذخیره (Commit) نشده است.
- **«اتصال به دیتابیس برقرار نشد»:** آدرس یا کلید اشتباه کپی شده (فاصله اضافه یا ناقص)، یا مرحله ۳ کامل اجرا نشده.
- **ورود نمی‌شود:** ایمیل و رمز را همان‌طور که در مرحله ۴ ساختید بنویسید. اگر هنگام ساخت کاربر تیک Auto Confirm User نخورده بود، کاربر را در Users پیدا کنید و تأیید کنید.
- **بعد از ورود دکمه‌های مدیریت نیامد:** صفحه را Refresh کنید. اگر باز هم نیامد، احتمالاً قبل از اجرای `schema.sql` کاربر ساخته شده؛ `schema.sql` را دوباره Run کنید (بی‌خطر است).
- **تغییر سایت دیر دیده می‌شود:** بعد از هر تغییر در GitHub تا ۲ دقیقه صبر کنید و صفحه را Refresh کنید.
